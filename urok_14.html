Аргументы в записях — аккуратный JSON вроде {"expression": "48763*9271"}. Обычно так и есть, но гарантии нет: поэтому в агенте json.loads стоит внутри try.

Как это работает

Три приёма: примеры, рассуждение, JSON

Сегодня три приёма — каждый попробуете сами:

Примеры · few-shot

Даём модели несколько решённых пар «фраза → ответ», чтобы она отвечала по тому же образцу. Как новичку в игре: пара сыгранных раундов понятнее длинных правил.

Рассуждение · chain-of-thought

Просим модель сначала записать ход мысли и только потом ответ. Как на контрольной: пишем решение, а не только ответ.

Структура · JSON

Ответ не сочинение, а анкета с полями. Программа берёт нужное поле по имени — и может его проверить и посчитать.
Новое · JSON mode

JSON mode: ответ строго в JSON

Чтобы модель ответила строго в формате JSON, в запрос добавляют response_format. У JSON mode три условия:

  1. В запросе response_format={"type": "json_object"}
  2. В промпте слово JSON и пример формата; без слова JSON модель может долго печатать пробелы
  3. Разумный max_tokens: хватает на весь JSON, но ответ не тянется бесконечно
PYTHON
SYSTEM = ("Определи настроение фразы. Ответь в формате JSON: " '{"mood": "настроение одним словом", "emoji": "один эмодзи"}') response = client.chat.completions.create( model="deepseek-flash", messages=[ {"role": "system", "content": SYSTEM}, {"role": "user", "content": "Ура, завтра каникулы!"}, ], response_format={"type": "json_object"}, # JSON mode: ответ — только JSON
Настройки классификатора

Строгий режим: temperature=0

На уроке 11 temperature меняла характер ответа: 0.2 — строго, 0.9 — творчески. Классификатору творчество не нужно: на одну и ту же фразу нам нужна одна и та же метка. Поэтому берём самый строгий режим — temperature=0.

PYTHON
response_format={"type": "json_object"}, # JSON mode: ответ — только JSON temperature=0, # самый строгий режим max_tokens=500, # предел длины ответа extra_body={"thinking": {"type": "disabled"}}, # выключаем режим размышлений )
Режим размышлений выключаем, как на уроке 13: в нём temperature молча не действует. А рассуждать модель всё равно будет — в правке 2 попросим её записывать ход мысли прямо в ответ JSON.

Если warmup.py не запустился

ошибка про api_key
Ключ не найден: .env не в папке lesson-14 или переменная называется не DEEPSEEK_KEY. В свежей версии openai SDK текст ошибки начинается с «Missing credentials».

ModuleNotFoundError
Выполните pip install openai python-dotenv; не сработало — py -m pip install openai python-dotenv.

Метки — как варианты ответа в тесте

Свободный ответ похож на сочинение, а нам нужен тест с вариантами ответа. Шесть меток перечисляем в промпте, а программа хранит тот же список в словаре EMOJI: метка → эмодзи.

PYTHON
EMOJI = { # наш список меток: метка → эмодзи "радость": "😊", "грусть": "😢", "злость": "😠", "страх": "😨", "удивление": "😮", "спокойствие": "😌", } SYSTEM = ( "Ты — классификатор настроения сообщений. Определи настроение фразы " "и выбери ровно одну метку из списка: радость, грусть, злость, страх, " "удивление, спокойствие. " 'Ответь в формате JSON: {"mood": "метка из списка"}' )
JSON mode следит только за тем, чтобы ответ был правильным JSON. Какая метка в нём окажется, зависит от промпта — поэтому список меток держим и в программе: по нему проверим ответ в правке 3.
Как это работает

Каждая фраза — отдельный запрос

Классификатор — не чат. Собеседник урока 12 помнил разговор, а здесь каждая фраза уходит отдельным запросом: только system и сама фраза. Иначе прошлые фразы влияли бы на метку новой.

PYTHON
def classify(text): messages = [ {"role": "system", "content": SYSTEM}, {"role": "user", "content": text}, # каждая фраза — отдельный запрос ] response = client.chat.completions.create( model="deepseek-flash", messages=messages, response_format={"type": "json_object"}, # JSON mode temperature=0, # классификатору нужна строгость max_tokens=500, extra_body={"thinking": {"type": "disabled"}}, # без режима размышлений ) content = response.choices[0].message.content or "" # строка от модели return json.loads(content) # строка JSON → словарь
json.loads превращает строку JSON в словарь — как json.load на уроке 7, только из строки, а не из файла. or "" подставит пустую строку, если ответ пустой, — как в стриминге урока 12.

Разбор кода

Примеры — как прошлый разговор

Примеры встают в messages между system и вашей фразой: user → assistant, и так четыре раза. Модель видит образец — какой ответ мы ждём на похожие фразы.

PYTHON
def classify(text): messages = [{"role": "system", "content": SYSTEM}] for phrase, answer in EXAMPLES: # примеры — как будто прошлый разговор reply = json.dumps(answer, ensure_ascii=False) # словарь → строка JSON messages.append({"role": "user", "content": phrase}) messages.append({"role": "assistant", "content": reply}) messages.append({"role": "user", "content": text}) # фраза, которую проверяем
Ответы assistant пишем мы сами, и они должны быть правильным JSON — таким же, какой ждём от модели. json.dumps превращает словарь в строку JSON без ошибок в кавычках, а ensure_ascii=False оставляет русские буквы читаемыми.
Полезное знание

Zero-shot и few-shot

Zero-shot: только инструкция

«Выбери одну метку из списка». Как понимать сарказм или строку из одних эмодзи, модель решает сама — и не обязательно так, как вы.

zero — «ноль»: ни одного примера

Few-shot: инструкция и примеры

Решённые пары «фраза → ответ» показывают ваши правила на деле: сарказм про неприятность — злость, тревожный 😬 — страх.

few — «несколько»: у нас четыре примера

Как выбирать примеры: разные метки, трудные случаи и ни одной фразы из phrases.txt — иначе проверка будет нечестной. Это общий приём для чат-моделей, поэтому проверяем его сами — на своих фразах.

Правка 2 · рассуждение

Сначала рассуждение, потом метка

Попросим модель записывать ход мысли до метки — в поле reasoning. Это chain-of-thought — цепочка рассуждений.

→ В тот же чат

Разбор кода

check: не верим ответу вслепую

check возвращает None, если из ответа не получился словарь или метки нет в списке. Тогда classify спрашивает модель ещё раз, а после второй неудачи программа пишет «🤔 непонятно». Если непонятна только уверенность, check ставит 0 и возвращает словарь — программа напишет «🤔 не уверен».

PYTHON
def check(content): try: data = json.loads(content) # строка JSON → словарь except json.JSONDecodeError: return None # пусто или не JSON if not isinstance(data, dict): return None # JSON, но не объект в фигурных скобках mood = str(data.get("mood", "")).strip().lower() # « Радость» → «радость» if mood not in EMOJI: return None # метки нет в нашем списке conf = data.get("confidence") if not isinstance(conf, (int, float)) or not 0 <= conf <= 100: conf = 0 # уверенность непонятна — считаем, что её нет data["mood"] = mood data["confidence"] = conf return data

Имя и текст — через двоеточие

line.split(":", 1) делит строку по первому двоеточию: слева имя, справа текст — даже если в самом сообщении есть ещё двоеточия. Строки без двоеточия программа пропускает.

PYTHON
def run_chat(): lines = (HERE / "chat.txt").read_text(encoding="utf-8").splitlines() for line in lines: if ":" not in line: continue # строка не в формате «Имя: текст» name, text = line.split(":", 1) # делим по первому двоеточию name, text = name.strip(), text.strip() if not text: continue # пустое сообщение пропускаем print(f"▶ {name}: {text}") show(classify(text))

Отладка

Читаем ошибки JSON

Ошибка разбора JSON в Python — JSONDecodeError. После двоеточия написано, что не так, а line … column … — где именно.

Expecting value
Строка пустая или вообще не JSON, например обычный текст. Проверьте response_format и слово JSON в промпте.
Extra data
В файле два JSON подряд: запись дописывали в конец. Файл-отчёт пишем режимом "w", а список читаем и сохраняем целиком.
Unterminated string
Строка в JSON не закрыта кавычкой — так бывает, если ответ оборвался на середине. Проверьте max_tokens.
Expecting property name enclosed in double quotes
Одинарные кавычки вместо двойных: так выходит, если писать JSON руками. json.dumps всегда пишет правильно.
KeyError: 'mood'
Ключа нет в словаре. Берите data.get("mood") и проверяйте ответ, как в check.
Непонятная ошибка — копируйте traceback целиком в тот же чат DeepSeek и просите объяснить и починить.
