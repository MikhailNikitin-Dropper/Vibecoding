Как это работает

Страница читает базу при каждом клике

С урока 16 вы знаете: нажали кнопку или выбрали другое значение в списке — Streamlit выполняет скрипт заново, сверху вниз. Значит, после каждого такого действия страница заново читает свежие строки из tracker.db.

  1. Открыли страницу, нажали кнопку или сменили фильтр — скрипт идёт сверху вниз
  2. SELECT читает строки из tracker.db — на странице таблица и график
  3. Нажали «Сохранить» в форме — INSERT и commit: запись в файле
  4. st.rerun() — скрипт снова сверху вниз, и новая запись уже на странице
st.session_state живёт, пока вкладку не закрыли и не обновили. tracker.db — файл на диске: записи переживут и обновление страницы, и Ctrl+C, и выключение компьютера.

Что храним

Одна тренировка — одна строка

В tracker.db будет одна таблица — workouts. Строка — тренировка, столбцы — её свойства.

id
Номер записи. Его даёт база, а нужен он для правки и удаления.
day
Дата строкой 2026-11-24: год, месяц, день. Так база правильно сравнивает и сортирует даты.
kind
Вид тренировки из списка: бег, прогулка, скакалка, отжимания…
minutes, amount
Минуты и количество: повторы или километры. Не считали — 0.
feeling, note
Самочувствие от 1 до 5 и короткая заметка до 100 символов.
Веса, калорий и сведений о здоровье в трекере нет. В заметку не пишем имён, адресов и названий секций: это ваш личный файл.

Разбор кода

Пишем в базу только по кнопке

change открывает соединение, выполняет команду, сохраняет изменение через commit и закрывает соединение. А вызывается INSERT только внутри if sent:.

PYTHON
def change(sql, params=()): # изменить базу: INSERT, UPDATE, DELETE with closing(connect()) as con: # соединение закроется само, даже при ошибке con.execute(sql, params) con.commit() # без commit изменение пропадёт … if sent: # в базу пишем только по кнопке формы error = check_values(day, note) if error: st.error(error) else: change( "INSERT INTO workouts (day, kind, minutes, amount, feeling, note) " "VALUES (?, ?, ?, ?, ?, ?)", (day.isoformat(), kind, int(minutes), float(amount), int(feeling), note.strip()), ) done(f"✅ Записал: {kind}, {minutes} мин")
done() кладёт сообщение в st.session_state и вызывает st.rerun(). Сообщение показываем уже после перезапуска: st.success прямо перед st.rerun() не успел бы появиться.

Разбор кода

GROUP BY считает, Python дополняет

База возвращает строки только за дни, когда были записи. Цикл проходит все дни подряд и ставит 0, где строки нет, — иначе пустые дни пропали бы с графика.

PYTHON

GROUP BY day", (start.isoformat(),), ) totals = {} # «2026-11-21» → 45 for r in rows: totals[r["day"]] = r["total"] labels, values = [], [] d = start while d <= date.today(): # все дни подряд, даже пустые labels.append(day_label(d)) values.append(totals.get(d.isoformat(), 0)) # нет записей — 0 минут d += timedelta(days=1) return labels, values

Вопрос 1

Одноклассник перенёс change("INSERT …") из ветки if sent: прямо под форму, без условия. В if sent: остался только st.success. Он открыл трекер, заполнил форму, один раз нажал «Сохранить», а потом два раза сменил период в сайдбаре. Сколько новых записей появилось в базе и почему?

Четыре вместо одной. Streamlit выполняет скрипт сверху вниз при открытии страницы, по кнопке и при каждой смене периода. INSERT без условия срабатывает в каждом запуске: при открытии записал значения формы по умолчанию, по кнопке — тренировку, а потом ещё две лишние записи. В базу пишем только внутри if sent:: кнопка отправки даёт True только в запуске, который начался с её нажатия.

Вопрос 2

В трекере три записи: пн 23.11 — бег 30 мин, пн 23.11 — отжимания 10 мин, ср 25.11 — прогулка 20 мин. SELECT day, SUM(minutes) AS total … GROUP BY day вернул две строки. Сколько дней с пн по ср будет на графике и какой высоты столбцы? Что случилось бы без нулей в minutes_by_day?

Три дня: пн — 40, вт — 0, ср — 20. GROUP BY day сложил минуты понедельника в одну строку. Вторника в ответе базы нет: в этот день записей не было. minutes_by_day проходит все дни подряд и ставит 0, где строки нет. Без нулей вторник исчез бы с графика, понедельник и среда встали бы рядом, и пропуск не был бы виден.
