Как это работает

Три работы — три запроса

Внутри репетитора нейросеть делает три разные работы. У каждой — свой запрос со своими настройками.

Объясняет · чат

Личность учителя в system, история чата и ответ по кусочкам через stream=True. Как на уроке 12, только в браузере.

Даёт задание · JSON

JSON mode, три решённых примера и temperature=0.9: задания разные, но всегда в одном формате.

Проверяет · инструменты

Калькулятор calculate и вердикт record_result, temperature=0: проверка должна быть строгой, а не творческой.
Во всех трёх запросах размышления выключены: extra_body={"thinking": {"type": "disabled"}}. Иначе temperature молча не действует, а проверка с tool_choice="required" получит ошибку 400.
Как это работает

Задание со скрытым ответом

Задание приходит не текстом, а анкетой в JSON — как метка настроения на уроке 14. Ученик видит только вопрос, а ответ и подсказку программа держит у себя.

JSON
{ "question": "Найди 15% от 240.", "answer": "36", "hint": "Сначала найди 1%: раздели 240 на 100.", "topic": "проценты" }
question — на экран. answer — только для проверки. hint — после неверного ответа. topic ставит сама программа из своего списка тем: так прогресс можно посчитать по темам.
Как это работает

Нейросеть проверяет себя калькулятором

Задачу придумала нейросеть, ответ записала тоже она. А вдруг ошиблась? Поэтому проверка не верит записанному ответу на слово.

  1. Ученик пишет ответ и нажимает «Проверить»
  2. Модель просит calculate("240*15/100") — программа считает: 36.0
  3. Модель сравнивает ответ ученика с калькулятором, а не с записанным ответом
  4. Вердикт — вызовом record_result: программа показывает ✅ или ❌ и записывает прогресс
Вердикт приходит не текстом, а аргументами вызова: correct — верно или нет, explanation — объяснение. Программе не нужно гадать по словам модели.

Типичные ситуации запуска

Если task_gen.py не запустился

«Не получилось, запусти ещё раз»
JSON mode изредка присылает пустой ответ. Это не ваша ошибка: запустите снова.
Ошибка про api_key
.env лежит не в lesson-16 или ключ в нём называется не DEEPSEEK_KEY.
Error code: 401 / 402
Ключ не принят (401) или на счёте школьного ключа кончились деньги (402). Ничего не меняйте — сообщите школе: на уроке — преподавателю.
ModuleNotFoundError
Выполните pip install openai python-dotenv; не сработало — py -m pip install openai python-dotenv.
deepseek-chat или client.responses в коде
Помощник взял старое имя или другой способ вызова. Верните как в промпте: deepseek-flash и client.chat.completions.create.
Как это работает

Вердикт — это вызов инструмента

На уроке 13 инструменты работали: узнавали время, считали. У record_result работа другая — модель заполняет анкету вердикта, а программа берёт ответы из аргументов.

PYTHON
RECORD_TOOL = { "type": "function", "function": { "name": "record_result", "description": "Записывает вердикт проверки. Вызови один раз, когда всё проверил.", "parameters": { "type": "object", "properties": { "reasoning": {"type": "string", "description": "Коротко: что требовалось и что ответил ученик"}, "correct": {"type": "boolean", "description": "true, если ответ ученика верный"}, "explanation": {"type": "string", "description": "Объяснение для ученика, 1–2 предложения"}, }, "required": ["reasoning", "correct", "explanation"], }, }, }
reasoning стоит первым, как на уроке 14: сначала рассуждение, потом вердикт. А tool_choice="required" обязывает модель вызвать инструмент — просто ответить текстом она не сможет.
Как это работает

Ключ — только в .env

Школьный ключ — как пароль от счёта школы. Он лежит в .env в папке lesson-16, а программа читает его так же, как на уроках 11–15. В самом коде ключа нет.

PYTHON
load_dotenv() # ключ берём из .env в папке lesson-16 KEY = os.getenv("DEEPSEEK_KEY") # сам ключ в коде не пишем if not KEY: st.error("Нет ключа DEEPSEEK_KEY: нужен файл .env в папке lesson-16") st.stop() # без ключа дальше не идём client = OpenAI(api_key=KEY, base_url="https://api.deepseek.com")
load_dotenv ищет .env рядом с app.py, а потом в папках выше — поэтому найдёт его в lesson-16. Нет файла — ошибки тоже нет, ключ просто пустой. Поэтому своя проверка: понятное сообщение и st.stop().

Счётчик, который говорит «стоп»

Перед каждым обращением к AI программа спрашивает can_spend(). Лимит исчерпан — предупреждение и False: запрос не уходит. Иначе счётчик в st.session_state растёт на 1, и запрос идёт дальше.

PYTHON

Вопрос 2

Ключ лежит в .env, в коде его нет, а репетитор работает только на вашем компьютере. Зачем тогда лимит обращений и max_chars?
