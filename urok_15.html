Как это работает

Модель ничего не помнит сама

Сервер нейросети не хранит ваш разговор: каждый запрос для него — с чистого листа. Помнит программа: в каждом запросе она заново отправляет весь список сообщений.

  1. Ход 1: system + ваша реплика
  2. Ход 2: system + реплика 1 + ответ 1 + реплика 2
  3. Ход 3: system + всё, что было, + реплика 3
  4. Ход 50: system + 99 сообщений — снова целиком
Как переписка с другом, который всё забывает: в каждое новое письмо вы вкладываете копии всех прошлых. С каждым разом письмо толще.
Как это работает

Токены и контекстное окно

Токен — кусочек слова. Нейросеть считает в токенах и вопрос, и ответ — и платят тоже за токены. Контекстное окно — предел: сколько токенов модель охватывает за один запрос. Чего нет в запросе, того для модели не существует.

deepseek-flash
окно 1 млн токенов
Kimi K3
1 048 576 токенов — тоже около миллиона
Русский текст
Сколько токенов в русском слове, документация не говорит. Точное число присылает сервер в поле usage
Окно огромное, но каждый ход отправляет всю историю — каждый следующий запрос длиннее и дороже. А документация Kimi предупреждает: рано или поздно история перерастёт окно. Поэтому память мы ограничим сами.

Как это работает

Один код — два провайдера

Меняются адрес base_url, имя модели и ключ. На уроке 11 мы говорили «меняются только адрес и ключ» — уточним: настройки размышлений у каждой нейросети свои.

PYTHON
deepseek = OpenAI(api_key=os.getenv("DEEPSEEK_KEY"), base_url="https://api.deepseek.com") response = deepseek.chat.completions.create( model="deepseek-flash", messages=messages, extra_body={"thinking": {"type": "disabled"}}, # размышления выключаем ) show("DeepSeek", response) if KIMI_KEY: # ключ Kimi есть только у преподавателя kimi = OpenAI(api_key=KIMI_KEY, base_url="https://api.moonshot.ai/v1") response = kimi.chat.completions.create( model="kimi-k3.1-pro", messages=messages, reasoning_effort="low", # K3 размышляет всегда; low — чтобы быстрее ) show("Kimi", response)
У DeepSeek режим размышлений включён по умолчанию — выключаем, как на уроках 13–14. Kimi K3 размышляет всегда, выключить нельзя, а temperature у неё фиксирована. Можно только выбрать глубину размышлений: reasoning_effort="low" — самый низкий уровень, с ним ответ приходит быстрее.
Как это работает

Счёт токенов в стриме

Сколько токенов ушло в запрос, сервер пишет в поле usage. В стриме ответ приходит кусочками, а счёт — в последнем из них. DeepSeek присылает его сам, а в документации Kimi счёт в стриме просят через stream_options. Просим и мы — так код подходит обоим.

PYTHON
stream = client.chat.completions.create( model="deepseek-flash", messages=request, stream=True, stream_options={"include_usage": True}, # счёт токенов — в последнем кусочке extra_body={"thinking": {"type": "disabled"}}, # без режима размышлений ) answer, usage = "", None print("Макс: ", end="", flush=True) for chunk in stream: if chunk.usage: # кусочек со счётом токенов usage = chunk.usage if chunk.choices: # кусочек с текстом ответа piece = chunk.choices[0].delta.content or "" print(piece, end="", flush=True) answer += piece
stream_options работает только вместе с stream=True, иначе сервер ответит ошибкой 400. В кусочке со счётом текста может не быть, а у Kimi в нём пустой даже список choices. Поэтому две защиты: проверка chunk.choices и or "".

Разбор кода

Две функции для файлов памяти

PYTHON
def load_json(path): try: with open(path, encoding="utf-8") as f: data = json.load(f) except FileNotFoundError: return {} # файла ещё нет — первая встреча except json.JSONDecodeError: print(f"{GRAY}⚠ {path.name} повреждён — начинаю с чистого листа{RESET}") return {} if not isinstance(data, dict): return {} # в файле не словарь — не наш формат return data def save_json(path, data): with open(path, "w", encoding="utf-8") as f: # "w" — перезаписать целиком json.dump(data, f, ensure_ascii=False, indent=2)

load_json всегда возвращает словарь: файла нет — пустой, файл сломан — пустой и предупреждение ⚠. save_json после каждого ответа перезаписывает файл целиком. Эта пара пригодится и для записной книжки в правке 4.

Режим "w" сначала очищает файл, а потом пишет. Прервёте программу через Ctrl+C прямо во время записи — файл может остаться недописанным. Поэтому загрузка стоит в try: битый файл не роняет программу.

Пересказ — отдельный запрос со своей инструкцией SUMMARY_PROMPT. Есть ключ Kimi — пересказывает Kimi. Ключа нет или Kimi ответил ошибкой — DeepSeek.

Разбор кода

Как факты попадают в книжку

PYTHON
def merge_facts(facts, new): added = {} # что узнали нового в этот ход for key, value in new.items(): if not value: continue # пустое значение не записываем if isinstance(value, list): # список: дописываем без повторов old = facts.get(key, []) if not isinstance(old, list): old = [old] fresh = [v for v in value if v not in old] if fresh: facts[key] = old + fresh added[key] = fresh elif facts.get(key) != value: # имя, возраст: новое вместо старого facts[key] = value added[key] = value return added

Модель только подсказывает, что нового. Решает программа, по нашим правилам: имя и возраст — новое значение вместо старого, списки — дописываем без повторов, пустое — пропускаем.

Факты лежат отдельным файлом и каждый раз целиком встают в system. Пересказ их не трогает — поэтому имя переживёт и сжатие, и перезапуск.

Вопрос 1

Петя заметил, что у deepseek-flash окно — миллион токенов, и решил: окно из 6 сообщений и пересказ не нужны, пусть программа шлёт всю историю. Прав ли он?
