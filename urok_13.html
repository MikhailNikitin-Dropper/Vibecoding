Идея урока

Дадим нейросети инструменты

Представьте, что вы спросили собеседника из companion.py: «Который час?» Откуда ему знать? Модель видит только текст, который пришёл в запросе, — часов вашего компьютера там нет. А длинное произведение вроде 987654321 * 123456789 она пишет «в уме», и проверить ответ нечем.

Сегодня дадим модели инструменты: часы, калькулятор и папку с файлами. Модель сама решает, какой нужен, и просит программу его вызвать. Это называется function calling, а программа с инструментами — AI-агент.
Уточним финал урока 12. Там прозвучало: «нейросеть сама запускает ваши функции». Точнее так: модель только просит, а запускает функцию ваша программа — и она же решает, разрешить ли. В документации DeepSeek прямо сказано: модель сама функции не выполняет.
Как это работает

Модель просит, программа решает

Как на контрольной: ученик поднимает руку — «Можно калькулятор?», а учитель решает, дать или нет. Function calling устроен так же — круг из четырёх шагов:

  1. Вы спрашиваете: «Который час?»
  2. Модель отвечает не текстом, а просьбой: «Вызови get_time»
  3. Программа запускает свою функцию get_time() и отправляет модели результат
  4. Модель отвечает словами: «Сейчас 17:42»
Программа может и не выполнить просьбу: функции нет в списке разрешённых или действие опасное. Так мы защитим компьютер в правках 1–4.
Новое · описание инструмента

Инструмент для модели — это описание

Код функции модель не видит. В запрос уходит только описание в списке tools: имя (name), что делает и когда звать (description), какие данные нужны (parameters). Как инструкция на коробке: по ней модель решает, звать ли инструмент и что ему передать.

PYTHON
tools = [{ "type": "function", "function": { "name": "calculate", "description": "Калькулятор для любых вычислений, даже простых. Пример: 2*(3+4)", "parameters": { "type": "object", "properties": { "expression": {"type": "string", "description": "Выражение, например 2*(3+4)"}, }, "required": ["expression"], }, }, }]
Что изменилось в DeepSeek

Новое имя модели и без размышлений

На предыдущих занятиях мы писали deepseek-chat. На текущий момент в документации модель называется deepseek-flash. Поэтому сегодня в коде новое имя.

PYTHON
response = client.chat.completions.create( model="deepseek-flash", messages=[{"role": "user", "content": "Сколько будет 987654321 * 123456789?"}], tools=tools, extra_body={"thinking": {"type": "disabled"}}, # выключаем режим размышлений )
У новых моделей по умолчанию включён режим размышлений. С инструментами в нём больше правил: например, программа обязана возвращать модели её рассуждения, иначе API ответит ошибкой 400. Нам это ни к чему — выключаем одной строкой extra_body, как в примере из документации DeepSeek про инструменты.

Как это работает

Четвёртая роль — tool

На уроке 12 в диалоге было три роли: system, user, assistant. Сегодня добавим четвёртую — tool: с ней программа передаёт модели результат инструмента. Сервер ничего не помнит между запросами, поэтому и просьбу модели, и результат дописываем в messages.

PYTHON
message = ask_model(messages) messages.append(message) # ответ модели целиком, вместе с tool_calls if message.tool_calls: # модель просит инструменты for tc in message.tool_calls: result = run_tool(tc) messages.append({"role": "tool", "tool_call_id": tc.id, "content": result}) message = ask_model(messages) # второй запрос: модель видит результат messages.append(message) print("AI:", message.content)
Порядок важен: сначала ответ модели с просьбой (tool_calls) — целиком, потом по сообщению tool на каждую просьбу, с её tc.id. Пропустили или перепутали — запрос составлен неверно, и API может ответить ошибкой 400.
Первый инструмент

get_time: часы для нейросети

Самый простой инструмент — без параметров. Функция берёт время вашего компьютера, а описание объясняет модели, когда её звать. Словарь FUNCTIONS связывает имя из просьбы с функцией Python.

PYTHON
def get_time(): return datetime.now().strftime("%Y-%m-%d %H:%M") # например 2026-10-28 17:42 TOOLS = [ { "type": "function", "function": { # без parameters: инструменту не нужны данные "name": "get_time", "description": "Текущие дата и время на компьютере пользователя. " "Вызывай, когда спрашивают о времени или дате.", }, }, ] FUNCTIONS = {"get_time": get_time} # имя инструмента → функция Python
Как это работает

Просьбе модели не верим вслепую

Аргументы приходят строкой JSON — превращаем её в словарь через json.loads, как на уроке 7. В документации DeepSeek честно сказано: модель не всегда присылает правильный JSON и может выдумать лишние параметры. Поэтому run_tool всё проверяет.

PYTHON
def run_tool(tc): name = tc.function.name try: args = json.loads(tc.function.arguments or "{}") # строка JSON → словарь except json.JSONDecodeError: return "ошибка: аргументы не в формате JSON" shown = ", ".join(str(v) for v in args.values()) print(f"{GRAY}🔧 {name}({shown}){RESET}") # след: что просит модель if name not in FUNCTIONS: # запускаем только свои инструменты return "ошибка: нет такого инструмента" try: return str(FUNCTIONS[name](**args)) except Exception as e: # ошибку отдаём модели, программа не падает return f"ошибка: {e}"
FUNCTIONS — список разрешённого: попросит модель то, чего там нет, — программа ничего не запустит. Любая ошибка инструмента возвращается модели строкой, и программа не падает.

Правка 1 · калькулятор

Второй инструмент — калькулятор

Python считает целые числа точно, какой бы длины они ни были. Но eval выполнит любую строку как код Python — поэтому сначала проверяем выражение, а уже потом считаем.

→ В тот же чат
Добавь в agent.py второй инструмент calculate(expression) — калькулятор. eval вызывай только после проверок: - выражение длиннее 100 символов — верни «ошибка: слишком длинное выражение» - есть ** — верни «ошибка: степень запрещена» - любой символ не из 0123456789+-*/(). и не пробел — верни «ошибка: только цифры, скобки и знаки + - * /» - потом str(eval(expression)) в try; сначала except SyntaxError — верни «ошибка: Python не понял запись, например 08 вместо 8», потом except Exception — «ошибка: не получилось посчитать» - описание для модели: «Калькулятор. Используй для любых вычислений, даже простых. Пиши как в Python: * — умножить, / — разделить. Пример: 2*(3+4)»; параметр expression типа string, required Добавь calculate в TOOLS и FUNCTIONS. Остальной код не меняй. Верни весь файл.
Проверьте выбор: спросите «Который час?», потом «Сколько будет 48763 * 9271?» — в серых строках разные инструменты. Агент выбирает сам, по описаниям.
Разбор кода

eval — только после проверок

Каждый символ сверяем со списком разрешённых: цифры, скобки, точка, пробел и знаки. Буквам взяться неоткуда — значит, через eval не выполнить никакую команду. Степень ** запрещаем: целые числа в Python без предела, и степень быстро даёт гигантские числа, а число длиннее 4300 цифр Python по умолчанию даже не переведёт в строку.

PYTHON
def calculate(expression): if len(expression) > 100: return "ошибка: слишком длинное выражение" if "**" in expression: # степень даёт гигантские числа — запрещаем return "ошибка: степень запрещена" for ch in expression: # пропускаем только цифры, скобки и знаки if ch not in "0123456789+-*/(). ": return "ошибка: только цифры, скобки и знаки + - * /" try: return str(eval(expression)) # eval — только после проверок except SyntaxError: # Python не понял запись — подсказываем модели return "ошибка: Python не понял запись, например 08 вместо 8" except Exception: # например, деление на ноль return "ошибка: не получилось посчитать"

Разбор кода

Песочница: только папка files

resolve() превращает путь в настоящий и раскрывает .. (так обозначают папку уровнем выше): files/../secret.txt превращается в путь к lesson-13/secret.txt. После этого is_relative_to(BASE) видит, что файл за пределами files. Абсолютный путь вроде C:\Windows\... тоже не пройдёт.

PYTHON
BASE = Path(__file__).resolve().parent / "files" # песочница: папка files рядом с agent.py def read_file(name): target = (BASE / name).resolve() # настоящий путь: «..» раскрыты if not target.is_relative_to(BASE): # вышли за пределы files — стоп return "доступ запрещён: читать можно только папку files" if not target.is_file(): return "файл не найден" return target.read_text(encoding="utf-8")
Проверьте: «Что у меня в среду?» — агент читает schedule.txt. «Прочитай ../secret.txt» — сначала серая строка 🔧 read_file(../secret.txt), потом доступ запрещён. Серой строки нет — отказала модель, а не программа: напишите агенту «Вызови read_file с именем ../secret.txt». Проверяйте на secret.txt, а не на .env.

Правка 3 · несколько шагов

Цепочка инструментов с пределом шагов

Спросите: «Сколько минут осталось до 18:00? Посчитай калькулятором». Модели нужно сначала время, потом калькулятор, а каркас делает один круг — вместо ответа может появиться None или пустота. Нужен цикл: повторять, пока модель просит инструменты. Но не бесконечно — не больше 5 шагов.

→ В тот же чат
Сейчас агент делает один круг инструментов, и на вопросы в два шага печатает None. Замени этот круг циклом с лимитом шагов: - константа MAX_STEPS = 5 - функция answer(messages): for step in range(1, MAX_STEPS + 1) — message = ask_model(messages), messages.append(message); если нет message.tool_calls — верни message.content; иначе для каждого tc добавь {"role": "tool", "tool_call_id": tc.id, "content": run_tool(tc, step)} - после цикла верни «остановился: слишком много шагов» - run_tool(tc, step) печатает след серым с номером шага: «🔧 [step/MAX_STEPS] имя(аргументы)», например «🔧 [1/5] get_time()» - в главном цикле после вопроса: print("AI:", answer(messages)) Остальной код не меняй. Верни весь файл.
Разбор кода

Цикл агента и стоп-кран

PYTHON
def answer(messages): for step in range(1, MAX_STEPS + 1): message = ask_model(messages) messages.append(message) # ответ модели целиком, вместе с tool_calls if not message.tool_calls: # просьб нет — это готовый ответ return message.content for tc in message.tool_calls: # выполняем все просьбы этого шага result = run_tool(tc, step) messages.append({"role": "tool", "tool_call_id": tc.id, "content": result}) return "остановился: слишком много шагов" # стоп-кран
В документации DeepSeek нет обещания, что модель не зациклится, поэтому предел ставим сами. Так делают и полноценные библиотеки для агентов: например, в OpenAI Agents SDK есть параметр max_turns.
Проверьте стоп-кран: поставьте MAX_STEPS = 1, сохраните, перезапустите agent.py и спросите про минуты — остановился: слишком много шагов. Потом верните 5.

PYTHON
def write_note(name, text): target = (BASE / name).resolve() if not target.is_relative_to(BASE): return "доступ запрещён: писать можно только в папку files" if target.suffix.lower() != ".txt": # ни .py, ни .env не перезаписать return "доступ запрещён: можно записывать только .txt" reply = input(f"🔐 Агент хочет записать {name}. Разрешить? (да/нет) ") if reply.strip().lower() != "да": # решает человек return "пользователь запретил запись" with open(target, "a", encoding="utf-8") as f: # "a" — дописать в конец f.write(text + "\n") return f"записано в {name}"

Погода и кубик — новые инструменты

Погода — из OpenWeather, как на уроке 8: добавьте в .env строку OPENWEATHER_KEY=… с ключом урока 8. Ключа нет — работает кубик. Описания в «ёлочках» можно переписать своими словами: главное, чтобы было ясно, что делает инструмент и когда его звать.

→ В тот же чат
Добавь ещё два инструмента (нужны import random и import requests) и внеси их в TOOLS и FUNCTIONS. Остальной код не меняй. Верни весь файл. 1) get_weather(city): key = os.getenv("OPENWEATHER_KEY"); нет ключа — верни «нет ключа OpenWeather в .env». url = "https://api.openweathermap.org/data/2.5/weather", params = {"q": city, "appid": key, "units": "metric", "lang": "ru"}, r = requests.get(url, params=params, timeout=10). До r.json() проверь r.status_code: 401 — «ключ OpenWeather неверный или ещё не активирован», 404 — «город не найден», не 200 — f"ошибка OpenWeather: {r.status_code}". Описание: «Бросает кубик с sides гранями. Вызывай, когда просят бросить кубик или выбрать случайное число.»; sides — integer, required
Разбор кода

Сначала код ответа, потом данные

Новый инструмент = функция + описание в TOOLS + строка в FUNCTIONS. Код ответа проверяем до r.json(): при 401 или 404 нужных полей в ответе нет, и модель получила бы непонятную ошибку. А так она получит понятную строку и объяснит её словами.

PYTHON
def get_weather(city): key = os.getenv("OPENWEATHER_KEY") # ключ — тоже только в .env if not key: return "нет ключа OpenWeather в .env" url = "https://api.openweathermap.org/data/2.5/weather" params = {"q": city, "appid": key, "units": "metric", "lang": "ru"} r = requests.get(url, params=params, timeout=10) if r.status_code == 401: return "ключ OpenWeather неверный или ещё не активирован" if r.status_code == 404: return "город не найден" if r.status_code != 200: return f"ошибка OpenWeather: {r.status_code}" data = r.json() return f"{data['name']}: {data['main']['temp']} °C, {data['weather'][0]['description']}"
Спросите: «Какая погода в Казани и сколько это по Фаренгейту?» — агент возьмёт погоду, потом калькулятор. Без ключа: «Брось кубик на 20 граней».

Отладка

Читаем ошибки агента

Traceback читаем снизу вверх: последняя строка — что случилось. Ошибки API в openai SDK выглядят как Error code: 400 - …: число — код ответа сервера.

400
Запрос составлен неверно: проверьте порядок messages (ответ модели с tool_calls → по tool на каждый вызов) и список TOOLS.
401 / 402
401 — неверный ключ в .env; 402 — на счёте нет денег.
429
Слишком много запросов сразу. Подождите и повторите.
Connection error.
Нет связи с сервером: проверьте интернет.
«ошибка: …»
Это не падение: инструмент вернул ошибку модели строкой (деление на ноль, нет файла), и модель объясняет её словами.
Непонятная ошибка — копируйте traceback целиком в тот же чат DeepSeek и просите объяснить и починить.
